# Generate graph

Transform metadata bundles generated by the metadata agent and their associated source
data into a graph for the filter stage. Make mapping decisions as an agent, then encode
them in reusable Python parsers so transformation can run again without an LLM.

Read [README.md](README.md) for scope, [DESIGN.md](DESIGN.md) for implementation decisions,
and [reference/parser_contract.md](reference/parser_contract.md) before generating a parser
or a build manifest. The graph builder and parser API version 1 are implemented; automated
parser generation and pipeline CLI integration remain pending. Keep supporting guidance in
`reference/`, utilities in `scripts/`, and tests in `tests/`.

## Understand the inputs

Read each source's `croissant.semantic.json` or gzip equivalent together with
`semantics_plan.json`, validation reports, and `notes.md`. Incorporate
`semantics_answers.json` when supplied. Resolve source files from the supplied inputs
and metadata rather than assuming a dataset location.

Extract record sets, entity groups, identifiers, Biolink classes and predicates, properties,
code mappings, and parsing dialects. Inspect relevant source records to check that metadata
matches the actual layout. Account for documented gaps and loading failures even when a
metadata validation report passes.

Some plan layouts refer to record sets only through opaque references generated by an earlier
tool run. If the available bundle provides no column-based or name-based way to identify the
physical file, skip that layout and report why; do not infer or guess the file. Before generating
a parser for an identified layout, compare its declared columns with the actual downloaded
file's headers. Drop declared columns absent from the real file and report affected mappings;
do not guess replacements or leave stale columns in the parser.

Reuse supported semantic mappings and their rationale. Do not treat local vocabulary terms
as Biolink terms or infer relationships solely from suggestive column names. Record any
additional mapping with its evidence and uncertainty. Where metadata lacks mappings, derive
them from source records and documentation when supported; existing annotations do not limit
the transform's coverage. Report unsupported content explicitly. Biolink is fixed and is not
a user-selectable ontology.

## Generate source parsers

Create a Python parser for each knowledge source with a `parse(source_files, metadata)`
entry point and `PARSER_API_VERSION = 1`. Yield dictionaries with `kind`, `data`, and `location`
according to [reference/parser_contract.md](reference/parser_contract.md). Node and edge payloads
follow the shared models before normalization; diagnostics carry a code, message, severity,
and whether content was skipped. Use helper functions for distinct source layouts and keep
imports free of execution side effects.

* Read the source formats and dialects declared in metadata, including compression,
  commented or absent headers, quoting, list separators, nested fields, and null values.
* Emit candidate nodes and edges with original identifiers, mapped categories and predicates,
  properties, and source lineage. Keep field extraction and relationship direction explicit.
* Construct CURIEs using documented namespaces, group fields belonging to the same entity,
  and apply code tables and conditional predicate mappings. Expand lists only when the
  relationship is defined; do not generate arbitrary combinations of independent lists.
* Preserve source files and columns for every edge, together with available publication
  evidence and mapping notes. Distinguish identifier cross-references from relationships.
* Emit diagnostics with file and row or record path for malformed records, missing required
  fields, and unsupported mappings.
* Keep LLM calls out of parser execution. Separate source parsing from shared normalization
  and graph assembly so the same graph builder can execute every generated parser.

Summarize planned node types, edge types, and known gaps before execution. Use strong defaults
without interactive questions. Transform all supported content; leave user selection,
affinity cutoffs, cross-source integration, augmentation, and conflict cleaning to later stages.

## Build the graph

Run [scripts/build_graph.py](scripts/build_graph.py) with a JSON build manifest listing parser
files, metadata document paths, local source files, and a per-source normalization policy:
strict exclusion or lenient retention of unresolved identifiers. Supply the pinned Biolink
vocabulary export described in the reference. Use saved normalization responses for offline
replay when supplied; do not silently fall back to live requests for missing snapshot entries.
Read [shared/schema.py](../../../../shared/schema.py) and
[shared/nodenorm.py](../../../../shared/nodenorm.py) before changing graph assembly.

1. Execute the parsers and collect candidate records with their lineage.
2. Pass every distinct candidate node identifier through `shared.nodenorm.normalize` in batches.
   Use `preferred_id` to obtain canonical IDs and inspect the raw response for labels,
   equivalent identifiers, and types. Respect the existing `NODENORM_URL` configuration.
3. For resolved nodes, use the canonical ID and prefer the source-mapped category if it is
   among NodeNorm's returned types; otherwise use the most specific returned type. Apply the
   hierarchy and tie rule in `DESIGN.md` across every parser and builder. For unresolved nodes,
   strict mode excludes them and affected edges; lenient mode keeps their original identifier
   and locally mapped category. Preserve input identifiers in `original_ids` for emitted nodes.
   NodeNorm supplies no source relationship semantics or provenance. Report unresolved IDs;
   never invent a canonical ID or treat a failed request as an unknown identifier.
4. Rewrite edge endpoints to the emitted canonical or retained node IDs and attach `Provenance`
   containing source, file, contributing columns, and available evidence. Preserve lineage when
   normalization collapses identifiers. Do not discard distinct source assertions during deduplication.
5. Construct and serialize a `Graph` through the shared Pydantic models. Keep properties
   within the supported scalar, null, and scalar-list value types. Preserve naturally
   multi-valued properties as lists; nested objects remain outside the shared property types.

Apply the per-source policy in [DESIGN.md](DESIGN.md), using lenient mode by default to retain
source-native identifiers unknown to NodeNorm. An unresolved identifier is a normal outcome
for some sources, not a service failure. Skip conflicting or malformed nodes, edges, or records
individually with diagnostics and continue the source build. Usable output with skipped records
is a successful partial result with status 0. Return nonzero only for structural failures such
as an unavailable required source file, unreachable normalization service, or parser crash.
Build a graph per source and report coverage and diagnostics.

## Validate and deliver

Check Biolink categories and predicates, canonical IDs or explicitly retained original IDs,
edge endpoint existence, and required provenance. Pydantic validation alone does not establish
semantic validity or graph referential integrity.

Test representative source records, dialect handling, both normalization policies, category
selection, record-level diagnostics, structural failures, endpoint rewriting, and provenance
preservation. Mock NodeNorm responses in tests; do not call the
live service. Verify that saved parsers can run again without regenerating them. Builder tests
under this skill's `tests/` directory are included in the repository's default `make test` run.

Deliver parser code, schema-valid graph JSON, and a report covering mappings, coverage,
skipped records, unresolved identifiers, and failures. Record source versions and checksums
where available, parser version, generation model ID, and normalization settings and response
snapshots needed to reproduce the run. Keep source dumps, graph outputs, and run artifacts
under gitignored `data/`; record source downloads in `data/README.md`. Check the current build
summary before consuming graph files: failed rebuilds may leave artifacts from earlier runs.

When connecting the implementation to `agents/transformation/cli.py`, preserve `DESCRIPTION`
and `main(argv: list[str] | None = None) -> int`. Support `main([])` with strong defaults,
return an exit code, and do not call `sys.exit` inside `main`. Keep the pipeline dry run
independent of network access and local data. Update `agents/transformation/README.md` when
CLI flags or input/output files change. Evaluation remains outside this agent.
